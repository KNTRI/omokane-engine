# 常態収束機仕様書

## 1. 概要

思兼神エンジンでは、重要な設計思想として **世界そのものがAIになる** 方向を採用する。

NPCだけが判断するのではなく、世界・場所・施設・Asset・勢力・環境そのものが状態を持ち、変化に反応し、秩序や機能を保とうとする。

この思想の中核概念として、**常態収束機** を導入する。

```text
常態収束機
= 現在状態と常態核の偏差を評価し、偏差を減らす復帰行動を選び、対象を常態へ収束させる制御機構
```

## 2. 通常のステートマシンとの違い

通常のステートマシンは、次のような状態切り替えとして扱われる。

```text
Idle -> Patrol -> Chase -> Attack
```

これは「現在どの状態にいるか」「次にどの状態へ移るか」を管理する仕組みである。

一方、常態収束機は、単なる状態切り替えではない。

```text
常態収束機
= 特定の安定状態へ戻ることを前提にした収束型ステートマシン
```

通常のステートマシンが「状態遷移」を重視するのに対し、常態収束機は「常態からの偏差」と「偏差を減らす復帰行動」を重視する。

## 3. 基本用語

以下の用語を定義する。

```text
常態
  その存在にとって本来維持されるべき安定状態。

常態核
  その存在が保とうとする中心的な状態・価値・秩序。
  NPCごと、場所ごと、Assetごと、勢力ごとに異なる。

偏差
  現在状態が常態からどれだけ逸脱しているかを表す差分。

復帰行動
  偏差を減らし、常態へ戻るために選ばれる行動。

常態収束機
  現在状態と常態核の偏差を評価し、偏差を減らす復帰行動を選び、
  対象を常態へ収束させる制御機構。
```

## 4. 基本構造

常態収束機とステートマシンの役割分担を、以下のように定義する。

```text
常態収束機 = 意思決定の原理
ステートマシン = 行動実行段階の制御
```

つまり、常態収束機が「何をするべきか」を決め、ステートマシンが「その行動が今どの段階か」を管理する。

```text
外部刺激
  ↓
現在状態が常態から逸脱する
  ↓
偏差が発生する
  ↓
常態収束機が偏差を評価する
  ↓
復帰行動を選ぶ
  ↓
ステートマシンが復帰行動の実行段階を管理する
  ↓
偏差が減る
  ↓
常態へ近づく
```

## 5. 設計文

思兼神エンジンにおける常態収束機の基本設計文は以下とする。

```text
思兼神エンジンでは、すべての主体は常態核を持つ。
外部刺激により現在状態が常態から逸脱すると、偏差が発生する。
常態収束機は偏差を評価し、復帰行動を選択する。
ステートマシンは、その復帰行動の実行段階を管理する。
```

## 7. 偏差と復帰行動の例

外部刺激によって常態から逸脱すると、偏差が発生する。

```text
空腹
  ↓
食事する

危険接近
  ↓
逃げる
  ↓
隠れる
  ↓
戦う
  ↓
通報する

雨
  ↓
屋根の下へ移動する

店の営業時間
  ↓
店番する

プレイヤーが暴れる
  ↓
村人が逃げる
  ↓
警備兵が調査する
  ↓
商人が店を閉める

森で火災
  ↓
動物が逃げる
  ↓
精霊が怒る
  ↓
村が警戒状態になる
```

## 8. NPCの扱い

この設計により、NPCは「プレイヤーのために配置された人形」ではなくなる。

NPCは、自分や所属世界の常態を回復しようとする端末として動く。

```text
NPC
= 自分の常態核と、所属する世界の常態核に反応する主体
```

NPCは単独で判断するだけではなく、場所、勢力、施設、Asset、環境の常態核と接続される。

## 9. 場所AI・Asset制御・勢力AIへの拡張

常態収束機はNPCだけに限定しない。

```text
NPC
  - 空腹、安全、日課、人間関係の常態を保とうとする

場所
  - 治安、清潔さ、混雑度、魔力濃度、危険度を保とうとする

施設
  - 営業状態、在庫、利用可能性、警備状態を保とうとする

Asset
  - 使用条件、耐久、封印、所有者、権能発動状態を保とうとする

勢力
  - 領地、資源、兵力、評判、外交関係を保とうとする

環境
  - 天候、生態系、災害、魔力循環、汚染度を保とうとする

世界
  - 複数の常態核を重ね合わせ、全体として自己修復・自己維持しようとする
```

## 10. 権能Assetとの関係

権能Assetは、世界・NPC・場所・Assetが選択できる復帰行動の部品になり得る。

```text
常態収束機
  ↓
偏差を評価する
  ↓
復帰行動を選ぶ
  ↓
復帰行動に必要な権能Assetを参照する
  ↓
権能Assetが安全な効果・イベント接続を提供する
```

ただし、権能Assetは任意コードを実行しない。
常態収束機が選ぶ行動も、エンジン側が定義した安全な権能・イベント・状態変更に限定する。

## 11. 言霊Eventとの関係

常態収束機は、復帰行動の結果として言霊Eventを発生させる。

```text
偏差検出
  ↓
復帰行動選択
  ↓
言霊Event発火
  ↓
他主体がイベントを受け取る
  ↓
別の常態核に偏差が発生する
```

これにより、世界全体に反応の連鎖が生まれる。

例:

```text
森で火災が発生する
  ↓
森の常態核に偏差が発生する
  ↓
森が火災Eventを発火する
  ↓
動物が逃げる
  ↓
村の警戒度が上がる
  ↓
兵士が調査へ向かう
  ↓
商人が店を閉める
```

## 12. 御魂Stateとの関係

常態核、現在状態、偏差、進行中の復帰行動は、実行時状態として保存・復元対象になり得る。

ただし、権能Assetと同様に、定義と実行時状態は混ぜない。

```text
常態核の定義
  - 何を保とうとするか
  - どの偏差を重視するか
  - どの復帰行動を選べるか

御魂State
  - 現在どれだけ逸脱しているか
  - どの復帰行動を実行中か
  - どのイベントを処理済みか
  - どの主体がどの状態にあるか
```

## 13. F#型イメージ

以下は将来的なF#型イメージであり、今回の作業では実装しない。

```fsharp
type 常態核ID = 常態核ID of string

type 偏差種別 =
    | 安全偏差
    | 空腹偏差
    | 秩序偏差
    | 在庫偏差
    | 魔力偏差
    | 環境偏差

type 偏差 =
    {
        種別: 偏差種別
        強度: float
        原因: string option
    }

type 復帰行動 =
    | 移動する of 目的地: string
    | 食事する
    | 逃げる
    | 戦う
    | 通報する
    | 店を閉める
    | 調査する
    | イベントを発火する of イベントID: string

type 常態核 =
    {
        ID: 常態核ID
        名称: string
        重視する偏差: 偏差種別 list
    }

type 常態収束判断 =
    {
        偏差一覧: 偏差 list
        選択された復帰行動: 復帰行動 option
    }
```

注意:

```text
この型イメージは概念整理用であり、v0.1で実装しない。
```

## 16. 設計原則

```text
1. NPCだけをAI主体にしない。
2. 世界・場所・施設・Asset・勢力・環境も常態核を持つ。
3. 常態収束機は、常態からの偏差を評価する。
4. 復帰行動は、偏差を減らすために選ばれる。
5. ステートマシンは、復帰行動の実行段階を管理する。
6. 権能Assetは、復帰行動の安全な部品として扱う。
7. 言霊Eventは、偏差と復帰行動の連鎖を世界へ伝える。
8. 御魂Stateは、実行時状態を保存・復元する。
9. 常態核の定義と実行時状態を混ぜない。
10. v0.1では思想と接続関係の文書化に留める。
```
