# 思兼神Core v0.1 F#型設計レビュー

## 1. 概要

思兼神Core v0.1 のF#型設計は、最小の固定tickゲームルールを安全に表すことを目的とします。

v0.1では、以下を最小単位として扱います。

```text
- 入力
- 位置
- 速度
- 当たり判定
- HP
- エンティティ
- ゲーム状態
- 終了状態
- 言霊Event
- 更新結果
- 検証結果
```

目的は、描画なしでもゲーム状態を進め、禊Testで検証できる状態にすることです。

この文書は、後続の実装作業で型や責務を増やしすぎないための実装前レビュー資料です。

## 4. 入力型

F#型イメージ:

```fsharp
type 入力 =
    | 左へ移動
    | 右へ移動
    | 上へ移動
    | 下へ移動
    | ジャンプ
    | 攻撃
    | 入力なし
```

設計方針:

```text
- 猿田彦Inputが外部入力をCore用入力へ変換する
- 思兼神Coreは外部デバイスに直接依存しない
- v0.1ではテスト用の入力列で検証する
```

今回の作業では実装しません。

## 5. 位置・速度型

F#型イメージ:

```fsharp
type 位置 =
    {
        X: float
        Y: float
    }

type 速度 =
    {
        X: float
        Y: float
    }
```

設計方針:

```text
- v0.1では単純なfloatで開始してよい
- 将来的には単位付き数値を検討する
- 位置と速度を混同しないよう、別型として扱う
```

将来候補:

```fsharp
[<Measure>]
type 秒

[<Measure>]
type px
```

## 6. 当たり判定型

v0.1では複雑化を避けるため、矩形または円のどちらか一方から始めます。

候補:

```fsharp
type 当たり判定 =
    | 矩形 of 幅:float * 高さ:float
```

または、

```fsharp
type 当たり判定 =
    | 円 of 半径:float
```

設計方針:

```text
- v0.1では1種類に絞る
- 衝突判定を先に検証しやすくする
- 2D固定tick避けゲーでは矩形の方が扱いやすい
```

推奨初期案:

```fsharp
type 当たり判定 =
    | 矩形 of 幅:float * 高さ:float
```

## 7. エンティティ型

F#型イメージ:

```fsharp
type エンティティID = エンティティID of string

type エンティティ種別 =
    | プレイヤー
    | 敵
    | 弾
    | 障害物

type 所有者 =
    | プレイヤー側
    | 敵側
    | 中立

type HP = HP of int

type エンティティ =
    {
        ID: エンティティID
        種別: エンティティ種別
        所有者: 所有者
        位置: 位置
        速度: 速度
        当たり判定: 当たり判定 option
        HP: HP option
    }
```

設計方針:

```text
- v0.1ではECSを作らない
- 単純なレコードで始める
- エンティティIDはstringの単純ラッパーにする
- HPが不要なものもあるため option にする
```

## 8. ゲーム状態型

F#型イメージ:

```fsharp
type 終了状態 =
    | ゲームオーバー
    | クリア

type ゲーム状態 =
    {
        Tick: int64
        プレイヤーID: エンティティID
        エンティティ一覧: エンティティ list
        乱数Seed: int
        終了状態: 終了状態 option
    }
```

設計方針:

```text
- Tickは固定tickの進行数を表す
- プレイヤーはエンティティ一覧内のIDで参照する
- v0.1ではMapではなくlistでもよい
- 必要になったらMapへ移行する
- 終了状態がSomeになったら不要な更新を止める
```

## 9. 言霊Event型

F#型イメージ:

```fsharp
type ゲームイベント =
    | Tick進行 of Tick:int64
    | エンティティ生成 of ID:エンティティID
    | エンティティ削除 of ID:エンティティID
    | 衝突発生 of A:エンティティID * B:エンティティID
    | ダメージ発生 of 対象:エンティティID * 量:int
    | ゲーム終了 of 終了状態
```

設計方針:

```text
- Coreは描画や音声を直接実行しない
- イベントとして外部へ返す
- Renderer、UI、ログは言霊Eventを見て処理する
```

## 10. 更新結果型

F#型イメージ:

```fsharp
type 更新結果 =
    {
        状態: ゲーム状態
        イベント一覧: ゲームイベント list
    }
```

設計方針:

```text
- 思兼神Coreの更新関数は更新結果を返す
- 状態だけでなくイベントも必ず返す
- テストでは状態とイベントの両方を検証する
```

## 11. 検証結果型

F#型イメージ:

```fsharp
type 検証結果 =
    | 正常
    | エラー of string list
```

設計方針:

```text
- 権能Assetや初期状態の検証に使う
- エラーは複数まとめて返す
- 最初のエラーで即停止しない
```

## 12. 権能Asset最小型の扱い

`docs/design/kengou_asset_spec.md` の内容を参照しつつ、v0.1では実装を急がない方針とします。

v0.1での扱い:

```text
- まずは思兼神Coreの固定tick更新を優先する
- 権能Assetは最小型候補と検証方針だけを設計する
- 外部JSON化はしない
- 任意F#コード実行は許可しない
- ファイル操作、ネットワーク処理、外部副作用は禁止
```

F#型イメージ:

```fsharp
type アセットID = アセットID of string

type 権能 =
    | 攻撃する of 威力:int
    | 回復する of 回復量:int
    | 状態を付与する of 状態名:string * 継続Tick:int
    | イベントを発火する of イベントID:string

type 発動条件 =
    | 入力時
    | 衝突時
    | Tick経過時 of int

type 権能Asset =
    {
        ID: アセットID
        名称: string
        発動条件: 発動条件 list
        権能一覧: 権能 list
    }
```

注意:

```text
これはv0.1用の最小候補であり、正式仕様は kengou_asset_spec.md を参照する。
```

## 13. v0.1では実装しない型・機能

以下はv0.1では作りません。

```text
- 高度なECS
- 3D座標
- 物理エンジン
- 外部JSON Asset
- アセット依存解決器
- セーブデータ形式
- Renderer接続
- 実デバイス入力
- ネットワーク
- 任意コード実行型Asset
```

## 14. 禊Testで最初に検証する項目

v0.1実装時に最初に作るテスト候補は次の通りです。

```text
- 初期状態を作れる
- Tickが1進む
- 入力なしでも決定論的に更新される
- 右入力でプレイヤーのX座標が増える
- 左入力でプレイヤーのX座標が減る
- 衝突する矩形同士を検出できる
- 衝突しない矩形同士を非衝突にできる
- HPが0以下になったらゲームオーバーになる
- ゲームオーバー後は不要な更新が進まない
- 同じ初期状態と入力列なら同じ結果になる
- 権能Assetの空ID・空名称・空権能一覧を検証エラーにできる
```

## 15. 実装時の最小ステップ案

今後の実装ステップ案は次の通りです。

```text
1. F#プロジェクト雛形を作る
2. 入力、位置、速度、エンティティ、ゲーム状態、言霊Event、更新結果の型だけを定義する
3. 初期状態を作る
4. Tickだけ進める更新関数を作る
5. 入力によるプレイヤー移動を追加する
6. 当たり判定を追加する
7. ゲームオーバー判定を追加する
8. 禊Testで決定論と不変条件を検証する
9. 権能Assetの最小型と検証器を別作業で追加する
```

## 16. 設計原則

```text
1. 最初は小さく作る。
2. ECSを急がない。
3. 外部データ化を急がない。
4. Rendererに依存しない。
5. 実デバイス入力に依存しない。
6. 固定tickを守る。
7. 同じ入力なら同じ結果を返す。
8. 状態とイベントを分ける。
9. 権能Assetは任意コードを実行しない。
10. 実装前に型の責務を確認する。
```
