# 因果認識閉ループ v0.1

## 1. 目的

正式な因果操作から地盤振動の権威伝播信号を生成し、主体固有の認識を経て `その場警戒` 行動候補へ到達する最小経路を定義する。
この経路は、World Truthの直接読取を使わず、原因、信号、認識、判断候補の由来を追跡できることを目的とする。

```text
因果操作
→ 地盤振動発生
→ 伝播信号
→ 感知値
→ 観測
→ 信念候補
→ 警戒意図
→ その場警戒 行動候補
```

## 2. 責務境界

この閉ループは、権威信号を生成し、一人の観測者について一件の行動候補を返すところで終了する。

行うこと:

- 因果操作と地盤振動発生操作の契約検証
- 原因因果IDと発生源EntityIDを固定した権威信号生成
- 既存の感知、観測、信念候補、警戒意図、行動候補APIの合成
- 非感知、警戒不成立、行動候補成立の区別

行わないこと:

- 信号移動、反射、遮蔽、寿命更新
- World Truthやゲーム状態の変更
- 複数候補の選択、行動実行、NPC反応の状態反映
- 因果台帳への追記、Replay、保存

## 3. シーケンス

```text
呼び出し側
  │
  ├─ ゲーム状態 + 地盤振動発生操作
  │      ↓
  │  地盤振動発生実行.適用する
  │      ├─ 失敗 → 地盤振動発生段階 Error
  │      └─ 成功 → 更新結果 + 正式信号 + 専用発生記録
  │                         ↓
  │                 地盤振動警戒経路.実行する
  │                         ├─ 非感知
  │                         ├─ 警戒不成立
  │                         └─ 警戒成立
  │                                  ↓
  │                         行動候補生成.警戒意図から作る
  │                                  ├─ Error
  │                                  └─ その場警戒候補
  │
  └─ 状態不変の更新結果と到達段階の中間値
```

## 4. 因果起点

`地盤振動発生操作` は、既存の `因果操作`、明示的な信号ID、発生位置、方向、強度、伝播方式、寿命Tickを持つ。
因果操作種別は `伝播信号生成` でなければならず、対象EntityIDは指定できない。
実行者IDは任意であり、`None` は地震、崩落、地形などEntity以外の発生源候補を表せる。

## 5. 伝播信号生成

実行器は量種別と媒体を `地盤振動`、`地盤` に固定する。
原因因果IDと発生源EntityIDは、因果操作のIDと実行者IDから自動設定する。
呼び出し側はこれらを別値へ差し替えられない。

地盤振動発生はPhase 1ではゲーム状態を変更しない。
正式信号は `更新結果` へ埋め込まず、独立した生成物として返す。

## 6. 認識境界

発生実行が返した正式信号を `地盤振動警戒経路.実行する` へそのまま渡す。
認識経路へ渡すゲーム状態はなく、現在Tick、観測者ID、観測位置、感知設定、正式信号、観測概要、仮説、事前確率、警戒設定だけを使用する。

距離計算、線形減衰、感度、感知閾値、確信度は既存 `感知値生成` の責務である。

## 7. 信念形成

感知値から観測、観測から信念候補への変換は既存APIへ委譲する。
閉ループは観測概要を解析せず、根拠と反証の分類や信念確率式を再実装しない。
Phase 1では一件の観測を一件の根拠として扱う。

## 8. 警戒意図

信念候補と明示警戒閾値の比較は既存 `警戒意図生成` が行う。
警戒意図はWorld Truthではなく、一時的な判断層の派生値である。
閾値未満はエラーではなく `警戒不成立` となる。

## 9. 行動候補

警戒成立時だけ、正式な警戒意図を `行動候補生成.警戒意図から作る` へ渡す。
生成される候補は `その場警戒` 一種類であり、選択済み行動、入力、因果操作、状態変更ではない。

## 10. Provenance Chain

最終成立時は次の由来鎖を保持する。

```text
発生操作.因果.ID
= 発生記録.因果操作ID
= 信号.原因因果ID |> Option.get

発生操作.因果.実行者ID
= 発生記録.実行者ID
= 信号.発生源EntityID

発生操作.信号ID
= 信号.ID
= 感知値.信号ID

入力.観測者ID
= 感知値.観測者ID
= 観測.観測者ID
= 警戒意図.観測者ID
= 行動候補.実行者ID

入力.仮説
= 信念候補.仮説
= 警戒意図.対象仮説
= 行動候補.対象仮説

信念候補.確率
= 警戒意図.警戒度
= 行動候補.優先度
```

## 11. Event境界

更新結果のEvent一覧は、地盤振動発生因果操作が明示したEventだけである。
感知、観測、信念候補、警戒意図、行動候補の各段階はEventを追加しない。
Eventは通知であり、伝播信号やWorld Truthそのものではない。

## 12. World Truth境界

地盤振動信号は認識対象となる権威信号である。
ただしPhase 1の発生実行は、ゲーム状態、Entity一覧、Tick、乱数Seed、終了状態を変更しない。
認識と行動候補生成もゲーム状態を受け取らないため、閉ループ成功後の更新状態は初期状態と構造的に等しい。

## 13. 失敗分類

発生実行は `契約不正` と `ゲーム内失敗` を区別する。
閉ループ公開APIは巨大なエラー階層を追加せず、理由へ次の段階名を付ける。

```text
地盤振動発生段階
認識段階
行動候補段階
```

バッチ発生は全件静的検証後に入力順で仮適用し、一件でも失敗すれば元状態だけを返す。
途中の信号、記録、Eventは公開しない。

## 14. 非感知と警戒不成立

`非感知` は距離範囲外または感知閾値以下など、感知値が正常に成立しなかった結果である。
`警戒不成立` は感知、観測、信念候補までは成立したが、信念確率が警戒閾値へ届かなかった結果である。
どちらも契約エラーではない。

## 15. 現在の因果台帳との関係

既存の `因果台帳記録` と `因果台帳再生` はEntity位置変更結果専用の互換APIとして維持する。
`地盤振動発生記録` は `統合因果台帳` へ位置変更記録と同じ正式因果順で保存でき、`統合因果台帳再生` は記録済み信号をそのまま再出力する。
対象EntityIDや変更前後位置のダミー値を作り、位置変更として偽装保存してはならない。

統合台帳のファイル保存、Snapshot、完全な入力・AI再実行は独立した後続設計とする。

## 16. 決定論

同じゲーム状態と構造的に等しい入力から、構造的に同じ結果を返す。
入力順を信号、記録、Eventの正式順序とし、MapやSetは検証検索にのみ使用する。
システム時刻、GUID、乱数、外部環境、並列完了順へ依存しない。

## 17. 今後の拡張

優先候補:

1. 行動候補の最小選択を設計する
2. 選択された `その場警戒` 候補からNPC状態反応要求を生成する
3. NPC状態反応を正式な因果操作として適用する
4. 統合因果台帳のファイル永続化とSnapshotを設計する
5. 地盤振動信号の寿命と時間発展を実装する
