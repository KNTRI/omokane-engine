# エンティティ反応要求

## 1. 目的

`選択済み行動候補` を、正式な世界変更や因果操作になる前の意味的な実行要求へ変換する。
Phase 1の終点は `エンティティ反応要求` であり、Entityやゲーム状態は変更しない。

## 2. NPCを正式API名に使わない理由

企画上はNPC反応を想定するが、現行の `エンティティ種別` にはNPC専用ケースがない。
プレイヤーとNPCを型上で厳密に区別できない段階で `NPC反応要求` と名付けると、存在しない適格性契約を装うことになる。
そのため公開APIは `エンティティ反応要求` とし、Entityの存在・種別・重複は後続の因果操作変換または実行器で検証する。

## 3. 三つの値の違い

- `行動候補` は、選択前の実行可能性を表す提案である。
- `選択済み行動候補` は、候補一覧、選択位置、選択候補を保持する判断層の派生値である。
- `エンティティ反応要求` は、選択結果を実行境界へ渡す意味的な要求である。

いずれもWorld Truthや行動結果ではない。反応要求もまだ因果操作ではない。

## 4. 反応要求ID

`エンティティ反応要求ID` は呼び出し側が明示する。
現在時刻、GUID、乱数、hash、行動候補ID、Tickから自動生成しない。
空白IDだけを契約不正として拒否する。

## 5. 発行Tick

反応要求のTickは、判断層から実行境界へ要求を発行したWorld Tickを表す。
呼び出し側が明示し、0以上でなければならない。

感知値や観測のTick、信号寿命、統合台帳末尾Tickから推測しない。
一つの候補一覧が異なる観測Tickを含められるため、観測時刻と要求発行時刻は別概念として維持する。

## 6. `その場警戒` の意味

Phase 1の `エンティティ反応種別` は `その場警戒` 一種類である。
これは主体が現在地点付近で警戒しようとする意味を表し、具体的な物理命令ではない。

## 7. 速度ゼロへ変換しない理由

`その場警戒` を `{ X = 0.0; Y = 0.0 }` へ直接変換しない。
警戒中でも落下、押し出し、慣性、足場移動などの物理状態は継続し得る。
locomotion意図、警戒状態、巡路状態、物理速度のどれを権威状態にするかは、次の因果操作設計で決定する。

## 8. private表現

`エンティティ反応要求` の判別共用体ケースはprivateである。
公開生成APIだけがID、Tick、実行者ID、種別、優先度、対象仮説、由来選択済み候補の整合した組を構築できる。

`選択済み行動候補` もprivate表現であるため、要求生成では候補一覧を再検証・再選択しない。
選択済み値の既存契約を信頼し、保存済み選択へ委譲する。

## 9. Provenance

要求は次の由来鎖を保持する。

```text
要求.実行者ID
= 選択済み.実行者ID
= 選択候補.実行者ID

要求.対象仮説
= 選択候補.対象仮説
= 選択候補.由来警戒意図.対象仮説

要求.優先度
= 選択候補.優先度
= 選択候補.由来警戒意図.警戒度

要求.由来行動候補ID
= 選択候補.ID
```

由来となる `選択済み行動候補` 全体を構造的に保存し、候補や警戒意図を再構築しない。

## 10. 選択理由と却下候補

要求の公開アクセサは、保存した選択済み値の既存アクセサへ委譲する。

- 由来候補一覧
- 由来選択位置
- 由来却下候補一覧
- 由来同率最高候補一覧
- 由来選択理由

候補一覧の再ソート、重複排除、選択位置の再検索は行わない。

## 11. World Truth境界

生成APIはゲーム状態、Entity一覧、位置、速度、HP、終了状態、乱数Seed、台帳を受け取らない。
反応要求生成によってEntity、ゲーム状態、Tick、位置、速度、HPは変化しない。

反応要求はWorld Truthではなく、実行前の意味的な派生値である。

## 12. Entity適格性境界

生成APIは実行者がNPC、プレイヤー、敵、弾、障害物のどれかを判定しない。
Entityの存在、重複、所有者、終了状態も検証しない。
これらはゲーム状態を受け取る後続の因果操作変換または実行器の責務である。

## 13. Event境界

反応要求生成はEventを返さず、既存Event一覧を変更せず、dispatchもしない。
警戒開始Eventや入力なしEventを暗黙生成しない。

## 14. Input境界

反応要求を既存 `入力` へ変換せず、`入力なし` と同一視しない。
既存のプレイヤー操作互換契約とAI由来の意味要求を混在させない。

## 15. 因果操作境界

反応要求生成は因果操作ID、因果操作種別、対象EntityID、発行予定Eventを作らない。
因果操作の実行、統合因果台帳追記、Replayも行わない。
反応要求は因果操作化の入力候補であり、正式な世界変更ではない。

## 16. 因果認識閉ループとの接続

同じ観測者について複数回の因果認識閉ループから行動候補を得て、`行動候補選択.選ぶ` へ渡す。
選択済み値と明示要求ID・Tickを要求生成へ渡すことで、信号ID、観測者ID、仮説、確率、警戒度、優先度、選択理由を保持した要求を得られる。

要求生成は閉ループの距離減衰、信念確率、警戒閾値、候補選択を再実行しない。

## 17. 統合Replayとの接続

`統合因果台帳再生` が再出力した正式信号から既存認識経路で候補を生成し、選択済み値を経て反応要求へ接続できる。
Replay信号を再構築せず、再生状態、Event一覧、統合因果台帳を変更しない。

## 18. 決定論

同じ要求ID、Tick、選択済み行動候補から構造的に同じ要求を返す。
現在時刻、GUID、乱数、外部環境、並列完了順、Dictionary、HashSet、Map列挙順へ依存しない。

候補の再選択、sort、優先度再計算、仮説解析、警戒意図再評価を行わない。

## 19. 次の因果操作化

後続設計では `その場警戒` をどの権威状態へ写像するかを先に決める必要がある。

- 物理速度を変更する
- locomotion意図を停止する
- 警戒状態をEntityとは別の権威状態として保持する
- 巡路状態を保持する

Phase 1ではいずれも採択しない。

## 20. 未実装事項

- 因果操作実行とWorld Truth反映
- Event発行と統合因果台帳追記
- 保存、Snapshot、Replay、Renderer接続
