# エンティティ反応状態と因果適用 v0.1

## 1. 目的

`エンティティ反応要求` を正式な状態変更因果操作へ変換し、意味を保った `その場警戒` をWorld Truthへ適用する。
成功結果を統合因果台帳の第三種として保存し、同じ初期状態から同じ反応状態を検証付きでReplayできるようにする。

## 2. 反応要求と反応状態

反応要求は判断層が実行境界へ渡す非権威の派生値である。
反応状態は因果操作が成功した後に `ゲーム状態` へ保存されるWorld Truthである。
要求を構築しただけでは状態は成立せず、privateな状態変更操作の検証と実行を必ず経由する。

## 3. `その場警戒` の権威意味

Phase 1の反応状態は、Entityについて「現在地点付近で警戒しようとしていることが正式に成立している」と表す。
物理速度ゼロ、位置固定、入力なし、巡路停止、警戒アニメーションのいずれとも同一ではない。

## 4. 物理速度と巡路からの分離

警戒中でも落下、慣性、押し出し、足場移動は継続し得る。
反応状態変更実行はEntityの位置、速度、HP、当たり判定、種別、所有者、Entity一覧順を変更しない。
`自発移動制御判断生成.ゲーム状態から作る` は反応状態を読み、状態なしを許可、`その場警戒` 中を自発移動抑制へ投影できる。
ただし現行Movementと巡路処理は判断をまだ参照せず、位置・速度・入力へは未接続である。

## 5. GameState公開契約

`ゲーム状態` は `エンティティ反応状態一覧: エンティティ反応状態 list` を持つ。
既存状態の初期値は空一覧であり、`終了状態` の公開型名とunion caseは `GameOutcome.fs` へ移した後も不変である。

## 6. 一Entity一反応状態Invariant

一覧内で同じ実行者IDを持つ反応状態は最大一件とする。
新規主体は末尾へ追加し、既存主体の更新は同じlist位置で置換する。ID順やTick順へ並べ替えない。
公開検索は不在を `Ok None`、一件を `Ok(Some state)`、重複を `Error` として区別する。

## 7. 状態の由来

privateな `エンティティ反応状態` は次を保持する。

- 成立因果操作ID
- 由来エンティティ反応要求

成立Tick、実行者ID、種別、優先度、対象仮説、要求ID、行動候補、選択位置、選択理由は、この二値と既存Provenanceから取得する。

## 8. 反応状態変更操作

`エンティティ反応状態変更操作生成.反応要求から作る` は、呼び出し側が明示した因果操作ID、原因因果ID、Eventと要求からprivate操作を作る。
操作種別は `状態変更`、実行者IDと対象EntityIDは要求主体、Tickは要求Tick、概要は固定文言となる。
要求IDや因果操作IDを時刻、GUID、乱数から生成しない。

## 9. 原因因果ID

原因因果IDは任意だが、空白IDと自己参照を拒否する。
地盤振動認識から生じた要求では、上流の正式因果IDを明示的に渡すことで因果鎖を保持できる。

## 10. 実行検証

契約検証は既存 `因果操作.検証する`、種別、要求とのTick・実行者・対象整合、自己参照を固定順で確認する。
契約成功後だけ、現在Tick、終了状態、対象Entityの存在・一意性、反応状態一覧Invariantをゲーム内検証する。
契約不正とゲーム内失敗を既存 `因果操作失敗分類` で分離し、失敗時は入力状態を返す。

## 11. 変更前・変更後状態

成功時は現在の対象反応状態を `変更前状態` とし、操作IDと由来要求から新しい `変更後状態` を作る。
正式記録は両状態、由来要求、原因因果ID、Eventを保持する。
更新結果のEventは操作が明示した一覧だけで、Tickを進めない。

## 12. 統合因果台帳の第三種

`統合因果記録` は次の三種をprivateな判別共用体で保持する。

```text
Entity位置変更
地盤振動発生
エンティティ反応状態変更
```

三種は明示的な分岐関数で処理し、別種のOption accessorをdispatchへ使わない。
因果操作IDとTickの共通Invariantに加え、反応要求IDを台帳全体で一意とする。
一件でも不正なら元台帳を返し、部分追記しない。

## 13. Replay

統合Replayは記録順に、記録契約、Tick、終了状態、対象Entity、反応状態一覧Invariant、変更前状態を検証する。
現在状態と `変更前状態` が構造的に一致した場合だけ、同じlist位置へ `変更後状態` を適用する。
一件でも失敗すれば初期状態へ原子的に戻し、途中Eventと途中信号を公開しない。

## 14. Event・Signal境界

反応状態変更は記録済みEventを台帳順・記録内順で再出力するが、Eventから状態を作らない。
反応状態記録は伝播信号を生成せず、既存の地盤振動信号一覧へ追加しない。

## 15. 完全技術経路

```text
地盤振動発生因果
→ 統合台帳と信号Replay
→ 感知値
→ 観測
→ 信念候補
→ 警戒意図
→ 行動候補
→ 選択済み行動候補
→ エンティティ反応要求
→ エンティティ反応状態変更因果操作
→ エンティティ反応状態
→ 統合台帳
→ Replay
```

認識段階はWorld Truthを直接読まず、反応要求は因果適用前まで非権威のままである。

## 16. 決定論

入力順を正式順とし、状態一覧、記録、Event、信号を再ソートしない。
時刻、GUID、乱数、外部環境、DictionaryやHashSetの列挙順へ依存しない。
正式禊Testは2160ケースを各2回実行し、live状態、Replay状態、Event、信号、list順の構造的一致を確認する。
