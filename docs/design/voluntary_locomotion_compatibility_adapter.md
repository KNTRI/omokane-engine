# 自発移動の互換移動命令Adapter v0.1

## 1. 目的

Gate結果を主体付き互換移動命令または説明可能な未生成結果へ投影する。今回の終点は互換移動変換結果である。

## 2. 現在の既存Movement制約

思兼神.更新するはゲーム状態.プレイヤーIDと一致するEntityを探し、プレイヤー種別の左右入力だけをX座標へ反映する。上下Inputは存在するが位置へ反映されない。

## 3. Inputだけを返さない理由

Inputは実行者IDを持たない。敵の意図をInputだけへ潰して渡すとプレイヤーを動かしかねないため、主体付き命令を次段の受け渡し単位にする。

## 4. 主体情報の保持

命令は由来Gate結果を保存し、Gate内の意図から実行者IDを取得する。プレイヤーIDへの置換は行わない。

## 5. 互換移動命令

private DUに命令種別と由来制御結果だけを保存する。Tick・主体・意図ID・方向・由来Inputを重複保存しない。

## 6. 命令種別

現行Movement対応の左へ移動・右へ移動だけを定義する。物理速度、移動距離、加速度を持たない。

## 7. 既存Inputへの投影

互換移動命令.既存入力は命令種別を網羅的matchし、左右Inputを返す。主体検証前にInputだけを抽出して実行してはならない。Input一覧だけを返すQueryは追加しない。

## 8. 通過結果

通過左・右は命令生成となる。命令から元のGate結果、意図、制御判断を構造的に辿れる。

## 9. 制御抑制

通過意図なしなら自発移動抑制を理由とする未生成結果。元の意図と抑制判断を保持する。

## 10. 方向未対応

通過上は上方向未対応、通過下は下方向未対応。命令と既存InputはNoneとなり、未対応方向アクセサは該当方向を返す。

## 11. 抑制を先に評価する理由

上流Gateで下流へ通さないことが確定していれば、Adapter能力は評価しない。抑制された上・下も方向未対応ではなく自発移動抑制となる。

## 12. 上下を黙ってno-opにしない理由

意図は妥当でも実装能力が不足する場合がある。正常な未対応理由を保持し、Error、入力なし、左右代替、成功扱いにしない。

## 13. 全域変換

自発移動互換変換.変換する : 自発移動意図制御結果 -> 互換移動変換結果。privateな入力契約を信頼し、Gate再実行やResultエラーを追加しない。

## 14. 一括変換

一括変換するは各Gate結果へのList.mapであり、空一覧は空。異なる主体・Tickや同一Gateの繰り返しも局所変換できる。

## 15. 入力順維持

一入力一結果。命令一覧・未生成結果一覧・抑制結果一覧・方向未対応結果一覧は順序を保つchoose/filterである。

## 16. 重複保持

一括Gateにおける意図ID一意性をAdapterで再検証しない。二度入力されたGateは二度変換する。方向の合成・相殺・裁定もしない。

## 17. Provenance

命令・結果 -> 保存Gate -> 意図(ID, Tick, 主体, 方向, Input由来) / 判断 -> 反応状態 -> 反応要求 -> 選択候補 -> 警戒意図 -> 信念 -> 観測 -> 感知値。要求ID・成立因果IDは既存アクセサへ委譲する。

## 18. Entity適格性境界

GameStateを受け取らずEntity存在・種別・所有者・locomotion能力を検査しない。敵・弾・障害物からも主体付き命令は生成可能であり、適用可能性は意味しない。

## 19. プレイヤーID検証の後送り

独立した [適用前検証](voluntary_locomotion_application_preflight.md) を追加した。命令主体とプレイヤーID、Tick、終了状態、Entity存在・一意性・プレイヤー種別、現在判断の許可と由来判断一致を確認する。互換変換自体はGameStateを受け取らず、契約を変更しない。

## 20. World Truth境界

互換命令と変換結果は一時的なCompatibility Boundaryの値で、権威状態でも位置変更結果でもない。Observationから続く実行計画の派生表現であり、Presentationの描画データでもない。

## 21. 物理状態境界

位置、速度、HP、当たり判定、重力、慣性、ノックバック、押し出しを参照・変更しない。自発移動抑制は物理速度ゼロを意味しない。

## 22. Input境界

Input.fsは無変更。既存Inputへの投影は左右命令だけを対象とする。非移動Inputは上流で意図なしとなりAdapterを呼ばない。

## 23. Movement境界

Systems/Omokane.fsは無変更。本番Adapterから思兼神.更新するを呼ばず、Tickも進めない。現行MovementはGateも互換命令もまだ読まない。

## 24. Event・因果・履歴境界

Event、更新結果、因果操作・記録を生成しない。統合台帳へ追記せずReplayも変更しない。正式履歴は因果適用結果を保存する。

## 25. 完全因果経路

正式地盤振動発生 -> 台帳 -> Replay信号 -> 感知・観測・信念・警戒 -> 候補・選択 -> 反応要求 -> 反応状態変更因果 -> World Truth -> 制御判断 -> Input由来右意図 -> Gate -> 互換変換。反応適用前は右命令、適用後は制御抑制となる。

## 26. 統合Replay

地盤振動と反応変更の正式記録を初期状態からReplayし、live状態とReplay状態の判断へ同じ意図を渡す。互換変換結果は構造的に一致する。信号・Event・台帳・状態は変換で変わらない。

## 27. Persistent Causal Worldとの整合

World Truth -> Derived Decision -> Execution Planning -> Compatibility Adapter -> 将来のRuntime適用。独立した変換規則を合成し、旧Movementの制約を意図や反応状態の正本へ逆流させない。Mesh、Input、物理速度を唯一のWorld Truthにしない。

## 28. 決定論

時刻、GUID、乱数、外部環境、非安定な列挙順に依存しない。単一変換はO(1)、一括とQueryはO(n)。Provenanceを参照保持し、深い再計算を行わない。LODや追加キャッシュは不要。

## 29. 将来のMovement適用Adapter

主体とGameStateの適用前照合はADR-029で実装済み。次は検証済みGameStateを保持する非空の適用準備だけを受け取り、別状態を渡せない適用Adapterへ進む。Inputだけの無条件実行は採用しない。

## 30. 未実装事項

GameState適用、上下・斜めMovement、速度・位置変更、入力filter、NPC巡路、意図競合解決、反応解除、期限、ヒステリシス、Event・因果・台帳保存、Field・SDF・Navigation・Rendererは後続である。プレイヤー主体の適用前適格性検証だけは独立境界で実装済み。
