# 思兼神Core v0.1 仕様書

## 1. 概要

思兼神Core v0.1 は、思兼神エンジンの最小中核です。

目的は、描画なしでもゲームルールを固定tickで更新し、自動テストで検証できる状態にすることです。

```text
思兼神Core v0.1
= 入力 + 現在状態を受け取り、次状態 + 言霊Eventを返す最小中核
```

v0.1では、描画、音声、エディタ、外部アセット読込を先に作らず、ゲームルールを安全に進める最小単位を文書化します。

## 2. v0.1で作るもの

v0.1で扱う範囲は次の通りです。

```text
- 固定tick更新
- 入力モデル
- ゲーム状態モデル
- 更新結果モデル
- 言霊Eventの最小形
- 天鳥船Motionの最小責務
- 建御雷Battleの最小責務
- 稲荷Asset / 権能Assetとの概念接続
- 禊Testの検証方針
```

この段階では、描画なしで状態更新を進め、テストで仕様を確認できることを優先します。

## 3. v0.1で作らないもの

v0.1では、次のものを作りません。

```text
- 描画エンジン
- 音声再生
- GUI
- エディタ
- 外部JSONアセット読込
- マーケットプレイス的なAsset管理
- 高度な物理エンジン
- 3Dレンダリング
- ネットワーク機能
- 任意コード実行型アセット
```

特に、権能Assetはv0.1では外部データ化しません。
初期段階では、F#型と検証器の設計に留めます。

## 4. 基本更新モデル

思兼神Coreの基本モデルは次の通りです。

```text
入力一覧 + 現在のゲーム状態
          ↓
      思兼神Core
          ↓
次のゲーム状態 + 言霊Event一覧
```

F#型イメージ:

```fsharp
type 更新結果 =
    {
        状態: ゲーム状態
        イベント一覧: ゲームイベント list
    }

let ゲームを更新する 入力一覧 現在状態 =
    // v0.1実装時に定義する
    未実装
```

今回の作業では実装しません。

## 5. 固定tick方針

思兼神Core v0.1では、固定tickを基本とします。

```text
- ゲーム状態更新は固定tickを基本とする
- 同じ初期状態、同じ入力列、同じシードなら同じ結果になる
- 描画フレームレートとゲーム更新tickを分離する
- 経過時間の揺らぎをゲームルールへ直接入れない
- 乱数はシード管理する
```

v0.1では、60 tick/sec を仮基準としてよいです。
ただし、実装前なので固定値を絶対視せず、仕様書上の初期案として扱います。

```text
1秒 = 60 tick
1 tick = 1 / 60 秒
```

## 6. 入力モデル

入力は、外部デバイスの状態を直接Coreに渡すのではなく、Core用の入力型へ変換して扱います。

担当:

```text
猿田彦Input
  - キーボード、ゲームパッドなどの外部入力を読む
  - Core用の入力型へ変換する

思兼神Core
  - 変換済みの入力だけを受け取る
```

F#型イメージ:

```fsharp
type 入力 =
    | 左へ移動
    | 右へ移動
    | 上へ移動
    | 下へ移動
    | ジャンプ
    | 攻撃
    | 入力なし
```

v0.1では、実デバイス入力ではなく、テスト用の入力列で検証できることを重視します。

## 7. ゲーム状態モデル

ゲーム状態は、固定tickごとに更新される実行時状態です。

F#型イメージ:

```fsharp
type ゲーム状態 =
    {
        Tick: int64
        プレイヤー: プレイヤー
        エンティティ一覧: エンティティ list
        乱数Seed: int
        終了状態: 終了状態 option
    }

type 終了状態 =
    | ゲームオーバー
    | クリア
```

v0.1では、必要最小限の状態のみを扱います。
描画用の一時状態や外部I/O状態をここへ混ぜ込まないことを優先します。

## 8. 言霊Eventの最小形

思兼神Coreは、描画や音声を直接実行しません。
状態更新の結果として、言霊Eventを返します。

F#型イメージ:

```fsharp
type ゲームイベント =
    | Tick進行 of Tick:int64
    | エンティティ生成 of ID:string
    | エンティティ削除 of ID:string
    | 衝突発生 of A:string * B:string
    | ダメージ発生 of 対象:string * 量:int
    | ゲーム終了 of 終了状態
```

これにより、CoreとRenderer、UI、ログ出力を分離します。

## 9. 天鳥船Motionの最小責務

天鳥船Motionは、移動・速度・座標更新を担当します。

v0.1の責務:

```text
- 位置を更新する
- 速度を反映する
- 固定tickに基づいて移動量を計算する
- 画面外判定や境界処理の方針を定める
```

F#型イメージ:

```fsharp
type 位置 =
    {
        X: float
        Y: float
    }

type 速度 =
    {
        X: float
        Y: float
    }
```

将来的には単位付き数値を検討します。

```fsharp
[<Measure>]
type 秒

[<Measure>]
type px
```

ただし、v0.1では実装複雑度を上げすぎないため、導入するかは別途判断します。

## 10. 建御雷Battleの最小責務

建御雷Battleは、戦闘・攻撃・衝突・ダメージを担当します。

v0.1では、本格的な戦闘システムではなく、最小の衝突・ダメージ方針のみ扱います。

```text
- 当たり判定
- 衝突発生イベント
- ダメージ発生イベント
- HPが0以下になった場合の終了状態
```

F#型イメージ:

```fsharp
type 当たり判定 =
    | 矩形 of 幅:float * 高さ:float
    | 円 of 半径:float

type HP =
    | HP of int
```

v0.1では、矩形または円のどちらか一方から始めてよいです。
両方を同時に作って複雑化しないでください。

## 11. 稲荷Assetと権能Assetの扱い

権能Assetは、稲荷Asset配下のルール付きアセットです。

ただし、v0.1では権能Assetを大きく実装しません。

v0.1での扱い:

```text
- 権能Assetは設計上の概念として参照する
- 実装する場合もF#型の最小定義と検証器まで
- 外部JSON化はしない
- 任意コード実行はしない
- ファイル操作、ネットワーク処理、外部副作用は禁止
- 固定tick上でイベントへ変換する設計だけ決める
```

権能Assetの実行方針:

```text
入力・衝突・イベント
  ↓
発動条件チェック
  ↓
権能Assetの権能を解釈
  ↓
言霊Eventまたは状態変更命令を生成
  ↓
思兼神Coreが固定tick上で反映
```

## 12. 更新順序

思兼神Core v0.1の更新順序を次のように定義します。

```text
1. 入力一覧を受け取る
2. 入力を現在状態へ適用する
3. Tickを1進める
4. 天鳥船Motionで位置・速度を更新する
5. 建御雷Battleで衝突・攻撃・ダメージを判定する
6. 権能Assetの発動条件を評価する
7. 権能を言霊Eventまたは状態変更命令へ変換する
8. 思兼神Coreが状態へ反映する
9. 終了条件を判定する
10. 更新結果として次状態と言霊Event一覧を返す
```

v0.1では、処理順序を固定し、同じ入力なら同じ結果になることを優先してください。

## 13. 禊Testの検証方針

禊Testは、思兼神Coreの安全性と再現性を検証します。

v0.1で検証したい項目:

```text
- 同じ初期状態と入力列なら同じ結果になる
- Tickが必ず1ずつ進む
- ゲームオーバー後に不要な更新が進まない
- 衝突時に衝突イベントが発生する
- HPが0未満へ無制限に落ち続けない
- 権能Assetに空ID、空名称、空権能一覧を許可しない
- 文字化けを含むRun Reportを出さない
```

今回の仕様書では、テスト項目の設計までとし、実テストは作成しません。

## 14. v0.1の最小サンプル題材

v0.1の検証題材として、固定tick避けゲーを採用します。

仕様例:

```text
- プレイヤーは左右移動できる
- 敵弾が一定tickごとに発生する
- 敵弾に当たるとゲームオーバー
- 生存tickをスコアとして扱う
- 同じシードと同じ入力列なら同じ結果になる
- 描画なしでもテストで進行を確認できる
```

## 15. 設計原則

```text
1. Coreは描画に依存しない。
2. Coreは入力デバイスに直接依存しない。
3. Coreは固定tickで更新する。
4. Coreは状態とイベントを返す。
5. 言霊EventによってRendererやUIと疎結合にする。
6. 権能Assetは任意コードを実行しない。
7. 御魂Stateと権能Assetを混ぜない。
8. 禊Testで決定論と不変条件を検証する。
9. 仕様変更と実装変更を混ぜない。
10. 最初は小さく作る。
```
