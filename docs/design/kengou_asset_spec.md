# 権能Asset仕様書

## 1. 概要

権能Assetは、UE6のスマートアセット的な概念を、思兼神エンジン向けに再定義したものです。

通常Assetが「素材」だとすれば、権能Assetは「ゲーム内で意味を持って動く定義体」です。

```text
通常Asset
= 参照される素材

権能Asset
= 条件を満たすとゲーム内で作用する、検証済みのルール付きアセット
```

権能Assetは、単なる画像・音声・モデル・データではありません。
ゲーム内での意味、条件、能力、イベント接続、検証規則を持つルール付きアセットです。

```text
権能Asset
= 意味・条件・能力・イベント接続・検証規則を持つ、F#向けのルール付きアセット
```

## 2. 基本定義

権能Assetは、アセット管理層で扱うアセットのうち、次の情報を持つものとします。

```text
- 一意なID
- 名称
- 種別
- タグ
- 使用条件
- 発動条件
- 権能一覧
- 依存Asset
- イベント接続
- 検証規則
```

Asset体系全体の中では、権能Assetは「能力・効果の部品」に位置づけます。
Entity生成の設計図は雛形Asset、既存Assetとの差分定義は派生Assetとして別に扱います。
Asset体系全体については `docs/design/asset_model_spec.md` を参照します。

## 3. 通常Assetとの違い

通常Asset:

```text
- 画像
- 音声
- フォント
- モデル
- 生データ
```

権能Asset:

```text
- 武器
- 技
- ユニット
- 地形効果
- 状態異常
- イベント部品
- UI部品
- 召喚定義
- ルール付きオブジェクト
```

通常Assetは参照されるだけです。
権能Assetは条件を満たすとゲーム内で作用します。

## 4. 命名意図

「権能」は、神や存在が持つ固有の能力・作用を意味します。

この名前を採用する理由:

```text
- 神具Assetよりも武器・道具に限定されない
- 依代Assetよりも機能・作用が明確
- 御魂Stateと意味が衝突しない
- 技術文書でも役割が見えやすい
```

重要:

```text
御魂Asset という名前は使わない。
御魂は State、つまりセーブ・復元・状態保存の用途で使用済み。
```

## 5. 権能Assetの役割

権能Assetは、ゲーム内で次のような役割を持ちます。

```text
- 攻撃する
- 回復する
- 状態異常を付与する
- イベントを発火する
- 召喚する
- 地形効果を発生させる
- UI操作を発生させる
- 条件を満たしたときだけ効果を発動する
```

ただし、任意コードを自由に実行するものではありません。
権能Assetは原則としてデータであり、実行できる処理はエンジン側が定義した安全な権能に限定します。

許可する例:

```text
- 攻撃する
- 回復する
- 状態を付与する
- イベントを発火する
- 召喚する
```

許可しない例:

```text
- 任意のF#コードを外部アセットから実行する
- ファイル操作を行う
- ネットワーク処理を行う
- エンジン外部へ副作用を出す
```

理由:

```text
「ファイルを削除する剣」のような最悪の神話を生まないため。
```

## 6. 配置

権能Assetは、アセット管理層である稲荷Assetの配下に置きます。

```text
稲荷Asset
  ├─ 通常Asset
  │    ├─ 画像
  │    ├─ 音声
  │    ├─ フォント
  │    └─ 生データ
  │
  └─ 権能Asset
       ├─ 種別
       ├─ タグ
       ├─ 使用条件
       ├─ 発動条件
       ├─ 権能一覧
       ├─ 依存Asset
       ├─ イベント接続
       └─ 検証規則
```

## 7. 他要素との関係

```text
稲荷Asset
  - 権能Assetの管理
  - 読み込み
  - ID管理
  - 依存関係管理
  - 参照解決

言霊Event
  - 権能Assetが発火するイベントを扱う
  - 通知やログを扱う

御魂State
  - 権能Assetによって変化した実行時状態を保存・復元する
  - 権能Assetそのものとは分ける

禊Test
  - 権能Assetの検証
  - 不変条件チェック
  - 破壊的な組み合わせの検出

思兼神Core
  - 権能Assetの効果を固定tick上で実行する
  - 状態更新順序を制御する
```

## 8. 権能Assetと御魂Stateの違い

```text
権能Asset
  - 実行前の定義
  - 何ができるか
  - どの条件で発動するか
  - 何のイベントを生むか
  - どのAssetに依存するか

御魂State
  - 実行後の状態
  - 何が保存されるか
  - どう復元するか
  - どの時点の状態か
```

短く言えば、以下です。

```text
権能Asset = 能力と条件を持つ定義体
御魂State = 保存・復元される実行時状態
```

この2つは混ぜません。

## 9. F#型イメージ

以下はF#型イメージです。
今回の作業では実装しません。

```fsharp
type アセットID = アセットID of string

type アセット種別 =
    | 武器
    | 防具
    | 技
    | ユニット
    | 地形
    | 状態異常
    | イベント
    | UI部品

type 使用条件 =
    | 必要レベル of int
    | 必要ロール of string
    | 必要タグ of string

type 発動条件 =
    | 常時
    | 入力時
    | 衝突時
    | 被ダメージ時
    | Tick経過時 of int
    | イベント受信時 of string

type 権能 =
    | 攻撃する of 威力:int
    | 回復する of 回復量:int
    | 状態を付与する of 状態名:string * 継続Tick:int
    | イベントを発火する of イベントID:string
    | 召喚する of アセットID

type 権能Asset =
    {
        ID: アセットID
        名称: string
        種別: アセット種別
        タグ: string list
        使用条件: 使用条件 list
        発動条件: 発動条件 list
        権能一覧: 権能 list
        依存Asset: アセットID list
    }
```

## 10. 権能Assetの例

```fsharp
let 火剣カグツチ =
    {
        ID = アセットID "weapon.fire_sword.kagutsuchi"
        名称 = "火剣カグツチ"
        種別 = 武器
        タグ = [ "片手剣"; "火属性"; "近接" ]
        使用条件 = [ 必要レベル 3; 必要ロール "アタッカー" ]
        発動条件 = [ 入力時; 衝突時 ]
        権能一覧 =
            [
                攻撃する 24
                状態を付与する ("炎上", 180)
                イベントを発火する "battle.fire_sword.hit"
            ]
        依存Asset = []
    }
```

この例では、火剣カグツチは単なる武器画像ではありません。
装備条件、発動条件、攻撃効果、状態異常、イベント発火を持つ権能Assetです。

## 11. 検証方針

権能Assetは、実行前に必ず検証します。

検証する項目:

```text
- IDが空でない
- IDが重複していない
- 名称が空でない
- 種別と権能が矛盾していない
- 発動条件が空でない
- 権能一覧が空でない
- 依存Assetが存在する
- 依存関係が循環していない
- 使用条件が不可能条件になっていない
- 威力や回復量が許容範囲内
- 固定tick上で再現可能
```

F#型イメージ:

```fsharp
type 検証結果 =
    | 正常
    | エラー of string list

let 権能Assetを検証する asset =
    [
        if asset.名称.Trim() = "" then
            yield "名称が空です"

        if List.isEmpty asset.発動条件 then
            yield "発動条件が空です"

        if List.isEmpty asset.権能一覧 then
            yield "権能一覧が空です"
    ]
    |> function
        | [] -> 正常
        | errors -> エラー errors
```

## 12. 実行方針

権能Assetは、直接ゲーム状態を書き換えません。

発動条件を満たしたとき、イベントまたは状態変更命令に変換され、思兼神Core側の固定tick処理で反映されます。

```text
入力・衝突・イベント
  ↓
発動条件チェック
  ↓
権能Assetの権能を解釈
  ↓
イベントまたは状態変更命令を生成
  ↓
固定tick上でCoreが反映
```

この流れにより、決定論的な実行とテスト再現性を保ちます。

## 13. 初期実装方針

最初から外部JSONやマーケットプレイス的な仕組みに広げません。
初期段階では、F#コード内で定義し、型と検証器で安全性を確保します。

初期ステップ:

```text
1. F#型で権能Assetを定義する
2. 権能Assetの検証器を作る
3. 武器・技・状態異常などのサンプルを作る
4. 固定tick上でイベントへ変換する
5. 自動テストで不変条件を確認する
6. 必要になってから外部データ化する
```

## 14. 設計原則

```text
1. 権能Assetは、単なる素材ではなく、検証済みのゲームルール部品として扱う。
2. 権能Assetは、原則としてデータであり、任意コード実行は許可しない。
3. 状態保存は御魂Stateに任せ、権能Asset自身に実行時状態を持たせすぎない。
4. イベント通知は言霊Eventに任せる。
5. 検証は禊Testで行う。
6. 実行順序と状態反映は思兼神Coreが管理する。
7. 描画素材とゲームルールを癒着させない。
8. 外部データ化は後回しにし、最初はF#型で堅く作る。
```

## 15. まとめ

```text
権能Asset
= 意味・条件・能力・イベント接続・検証規則を持つ、F#向けのルール付きアセット
```

目的は、アセットを「ただ置く素材」ではなく、検証済みのゲームルール部品として扱うことです。

自由度よりも安全性と再現性を優先します。
そのため、権能Assetは任意コードを実行せず、エンジン側が定義した安全な権能だけを持ちます。
