# 互換移動命令のGameState適用前検証 v0.1

## 1. 目的と現行Movement制約

主体付き命令を現在GameStateへ適用できるか純粋に確認する。現行MovementはInputをプレイヤーIDかつプレイヤー種別へ適用するため、主体照合前にInputだけを取り出して実行してはならない。
本境界はObservationから続く実行計画の適用前検証であり、World TruthでもPresentationでもない。AIへ世界真実直読を追加するものではない。

## 2. 適用準備とGameStateスナップショット

`互換移動適用準備` はprivate DUで、検証したGameState、対象Entity、再導出した現在制御判断、非空命令一覧を保持する。
対象状態・Entity・判断・命令一覧、命令数、単一命令option、既存入力一覧、Tick、プレイヤーID、実行者ID、意図ID一覧、命令種別一覧、方向一覧を公開アクセサから取得する。
単一命令はちょうど一件の場合だけSome。各一覧は元の順序を保持する。

これは検証対象と命令を結び付けた短命Capabilityであり、新しい権威状態ではない。状態Bを別途作っても準備が保持する状態Aは変化しない。
将来の適用Adapterは準備だけを引数に取り、別GameStateを受け取らない構造を推奨する。単回消費・現在世界とのcommit整合性はまだ保証しない。保存・シリアライズ・ネットワークへ使わない。

## 3. 単一準備・一括準備・空一覧

`単一を準備する : ゲーム状態 -> 互換移動命令 -> Result<互換移動適用準備, string list>`
`一括を準備する : ゲーム状態 -> 互換移動命令 list -> Result<互換移動適用準備 option, string list>`

両者は同じ非空検証を共有する。一括の空一覧はGameStateが不正でも `Ok None`。適用対象なしは正常であり、空準備、ダミー命令、入力なしへ変換しない。
後続で誤って `思兼神.更新する []` を呼び、命令なしでもTickだけ進むことを防ぐためである。

## 4. 現在制御判断の再導出

`自発移動制御判断生成.ゲーム状態から作る 状態.プレイヤーID 状態` へ委譲する。
Entity存在・一意性、状態Tick、反応状態一覧重複、未来成立Tickを複製しない。
既存エラーは `現在の自発移動制御判断: ` を付け、その順序を維持する。

## 5. 検証順と失敗

1. 現在制御判断の導出エラー。
2. 終了状態。ゲームオーバーとクリアを拒否する。
3. 導出成功時に取得した対象Entityの種別がプレイヤーか。
4. 全命令のTick一致エラーを入力順で収集。
5. 全命令の実行者IDと現在プレイヤーID一致エラーを入力順で収集。
6. 現在判断が抑制なら拒否。
7. 各命令の由来制御判断と現在判断の構造的一致。
8. 自発移動意図IDの重複。

現在判断失敗時は種別・抑制・由来比較を省略し、それ以外の独立エラーは収集する。
現在抑制時は由来比較を省略する。当該命令の主体/Tickが既に不一致の場合も二次的な由来比較を省略する。
エラーを途中で打ち切らず、後方不正でも部分準備を一件も公開しない。

## 6. 主体・Entity・Tick境界

対象プレイヤーIDのEntity一件だけを使い、その種別はプレイヤーに限定する。別IDのプレイヤー種別Entityは存在してよい。
非プレイヤー命令をプレイヤーへ昇格させない。古いTickも未来Tickも不一致として拒否し、補正・再発行しない。
読み取り判断自体は終了状態やEntity種別を抑制理由にしない。それらは今回の適用可能性の追加条件である。

## 7. 古い命令と現在抑制

```text
状態A: 反応なし -> 許可判断 -> 右命令
同じTickで反応状態因果適用
状態B: その場警戒 -> 現在抑制
状態Aの命令 + 状態B -> Error、準備なし
```

Tickだけを検証しても不十分である。他Entityだけの反応状態は対象判断を妨げない。
主体/Tickが一致する現在の許可判断は必ず反応状態なし・Noneなので、由来判断だけの不一致は公開APIから作れない。防御的比較は残すが、reflectionや本番テスト専用APIで不正値を捏造しない。

## 8. 一意性・入力順・方向非相殺

意図IDは一覧内で一意とする。同方向で異なるIDは別命令として保持する。
ID辞書順ソート、重複排除、主体group化、左右相殺、命令圧縮はしない。右・右・左はそのまま三件である。
既存入力一覧は命令種別の既存アクセサへ委譲する。Test内でのみ旧Movement結果との等価性を確認する。

## 9. 物理状態非依存とWorld Truth境界

所有者、位置、速度、HP、当たり判定を適格性へ使わない。これらが変わっても同じ制御判断なら受理し、現在の不変GameState全体を保持する。
自発移動抑制は落下、慣性、外力、押し出しを止める意味ではない。
準備だけではGameState、Entity、位置、速度、Tick、Seed、終了状態を変更しない。

## 10. Input・Movement・Event・因果・履歴境界

Input.fs、Systems/Omokane.fs、統合因果台帳、統合Replayは無変更。
本番preflightはMovementを呼ばず、更新結果、Event、因果操作、履歴記録を生成しない。
正式履歴の権威値は因果適用された反応状態であり、準備は保存しない。

## 11. 完全因果経路と統合Replay

```text
地盤振動因果 -> 台帳 -> 正式信号Replay -> 感知 -> 観測 -> 信念 -> 警戒
-> 候補 -> 選択 -> 反応要求 -> 反応状態因果 -> World Truth
-> 現在制御判断 -> 意図 -> Gate -> 互換変換 -> 適用前検証
```

反応前は右命令の準備に成功する。反応後は新Gateが抑制して命令なしとなり、一括準備はOk None。
反応前の古い命令はlive状態・Replay状態の双方で同じ抑制Errorとなる。
現在抑制判断から反応要求、候補、警戒、信念、観測、感知、信号、成立因果へ辿る。古い許可命令に後から反応由来を注入しない。
検証によりGameState、Event、Replay信号、台帳は変化しない。

## 12. Persistent Causal World・決定論

World Truth -> Derived Decision -> Execution Planning -> Compatibility Adapter -> Application Preflight -> Future Runtime Application。
独立した変換規則を合成し、既存Movementの制約を意味的意図の正本へ逆流させない。FieldやMeshをこの境界へ持ち込まない。
現在時刻、GUID、乱数、並列完了順に依存しない。ID件数検査の列挙は出力順へ使わない。
正常3,072・不正80ケースのMatrixで構造的一致、snapshot保持、入力順、固定Errorを検証する。軽量の一主体処理であり、LODや保存を追加しない。
