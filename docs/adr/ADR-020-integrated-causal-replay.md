# ADR-020: 統合因果Replayは状態変更と伝播信号生成を同一因果順で検証付き再適用する

- Status: Accepted
- Date: 2026-08-09

## Context

位置変更専用の既存Replayはゲーム状態とEventを再構築できるが、地盤振動発生結果は同じ正式因果順へ含まれていなかった。
地盤振動の再生では入力、AI、因果操作実行器、媒体伝播を再実行する情報は保持しておらず、記録済み信号を結果として扱う必要がある。
言霊Eventは通知であり、World Truthそのものではない。

## Decision

- `統合因果台帳再生` は統合台帳を保存順で検証付き再適用する。
- Entity位置変更は、既存Replayと共有するinternalな一件適用helperで状態へ反映する。
- 地盤振動発生は、記録済みの正式な伝播信号を構造的にそのまま再出力する。
- Tickは各記録Tickへ進め、同一TickとTickの飛びを許可し、逆行を拒否する。
- Eventは台帳順・記録内順で再出力するだけで、状態を変更しない。
- 信号寿命、移動、反射、遮蔽、減衰、合成をReplay時に計算しない。
- 一件でも失敗した場合は初期状態を返し、途中状態、Event、信号を公開しない。
- 既存の位置変更専用 `因果台帳再生.再生する` を維持する。

## Consequences

- 世界状態と認識用の権威伝播信号を、一つの正式履歴から決定論的に再構築できる。
- 再生信号を既存の地盤振動認識経路へ渡し、警戒意図と行動候補を再構築できる。
- これは記録済み結果のReplayであり、入力、AI、権能、乱数を再実行する完全な記紀Replayではない。
- 任意時点Replay、Snapshot、永続化、信号時間発展は後続となる。

## Implementation Status

実装済み:

- 位置変更と地盤振動発生の混在因果順Replay
- 状態、Event、伝播信号の決定論的な再構築
- 地盤振動発生元と位置変更前提の検証
- 後方失敗時の原子的復帰
- 既存Replayと移行済み統合Replayの等価性検証

未実装:

- 入力列、AI判断、権能評価、乱数消費の再実行
- Snapshot、巻き戻し、途中位置からのReplay
- Event dispatch、信号寿命更新、媒体伝播
