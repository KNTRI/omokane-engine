# ADR-029: 互換移動命令は検証済みGameStateと一体の適用準備を経て旧Movementへ渡す

- Status: Accepted
- Date: 2026-09-08

## Context

- 主体付き互換命令は存在するが、現在GameStateへの適用可能性を確認する境界がなかった。
- 現行MovementはInputの主体を持たず、プレイヤーIDかつプレイヤー種別を対象にする。Inputだけを渡すと非プレイヤー意図が誤適用され得る。
- 同じTickでも命令生成後に警戒状態が成立し、古い許可命令が残る。
- 検証状態と適用状態を別引数にすると、異なる状態へ適用する取り違えが起き得る。

## Decision

- privateな `互換移動適用準備` に検証済み不変GameState、対象Entity、現在制御判断、非空命令一覧を保存する。
- 現在判断は既存の `自発移動制御判断生成.ゲーム状態から作る` へ委譲し、存在、一意性、反応状態一覧、未来成立Tickの規則を複製しない。
- 終了状態を拒否し、対象Entityのプレイヤー種別を要求する。終了状態は読み取り判断の理由には混ぜない。
- 全命令のTick、実行者IDを現在Tick、プレイヤーIDと照合する。現在判断の許可と命令由来判断の構造的一致を要求する。
- 意図ID重複を拒否し、全エラーを固定順で収集する。一件でも不正なら部分準備を公開しない。
- エラー順は現在判断、終了、種別、全命令Tick、全命令主体、現在抑制、由来判断、ID重複とする。
- 判断導出失敗時は種別・抑制・由来判断を検証しない。抑制時、または当該命令の主体/Tick不一致時は二次的な由来比較エラーを追加しない。
- 空一覧はGameState検証なしで `Ok None` とする。空準備やダミーInputを生成しない。
- 単一と一括は共通の非空検証を使い、入力順・各命令を保持する。方向相殺、圧縮、sort、group化を行わない。
- 準備は短命の非権威Capabilityとする。後続Adapterは別GameStateを受け取らず準備だけを使う設計とし、本段階では実行しない。

## Consequences

- 非プレイヤー命令と同Tickの古い許可命令を、旧Movementへ渡す前に拒否できる。
- 状態Aで検証した結果を状態Bへ差し替える誤用を、状態保持により避ける構造になる。
- 準備の保持期間は短くする。単回使用や現在世界へのcommit保証はまだなく、保存、ネットワーク送信、台帳記録には使わない。
- 物理値が変わっても同じ制御判断なら受理し、検証時点の状態を保持する。所有者、HP、位置、速度、当たり判定は適格性条件ではない。
- 現行の許可判断では主体/Tick一致後の由来判断不一致は公開APIから構築できない。将来に備えた構造比較を残し、テスト専用の偽造APIは追加しない。
- 位置変更、Tick進行、Event生成は発生しない。ADR-003はProposedを維持する。

## Implementation Status

実装済み: 単一・一括preflight、private準備、現在判断再導出、主体・Tick・Entity・終了検証、stale拒否、原子性、ID一意性、完全因果経路・Replay接続検証。

未実装: 準備からMovementを実行するAdapter、上下・任意Entity Movement、旧Input経路廃止、意図競合解決、反応解除、履歴永続化。
