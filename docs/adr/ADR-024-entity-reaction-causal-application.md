# ADR-024: エンティティ反応要求は状態変更因果操作を経由して適用・記録・再生する

- Status: Accepted
- Date: 2026-08-13

## Context

- 反応要求を直接ゲーム状態へ書き込むと因果境界を迂回する。
- 統合因果台帳は位置変更と地盤振動を扱っていたが、反応状態変更には未対応だった。
- 反応要求の判断由来を正式履歴へ保持し、live実行とReplayを一致させる必要がある。

## Decision

- 反応要求からprivateな `エンティティ反応状態変更操作` を生成する。
- 因果操作ID、原因因果ID、Eventは呼び出し側が明示する。
- 実行者IDと対象EntityIDは、反応要求の主体へ固定する。
- 実行器は変更前状態と変更後状態を正式記録へ保存する。
- 統合因果台帳へ第三の記録種別として保存する。
- Replayは変更前状態を前提条件として、保存順に反応状態を再適用する。
- エンティティ反応要求IDを統合台帳全体で一意とする。
- 三種の統合記録は明示的な判別共用体分岐で処理し、Optionによる暗黙dispatchを使わない。

## Consequences

- 世界の判断結果を正式な因果としてWorld Truthへ反映できる。
- live実行とReplayの反応状態を構造的に一致させられる。
- 位置、速度、HP、巡路は変更されない。
- 解除、競合、複数状態、継続時間は後続となる。

## Implementation Status

実装済み:

- 要求からprivate操作への固定写像
- 契約不正とゲーム内失敗を分離する単体実行器
- 変更前後状態と由来要求を持つ正式記録
- 統合因果台帳の第三種、要求ID一意性、原子的追記
- 変更前状態を検証する三種統合Replayと原子的復帰

未実装:

- 反応状態変更の異種バッチ
- 複数要求の競合裁定、結界Lock、天津裁定
- 警戒解除、Movement解釈、永続ファイル保存、Snapshot
