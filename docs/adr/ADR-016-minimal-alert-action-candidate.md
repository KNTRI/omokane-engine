# ADR-016: 警戒意図からの最小行動候補生成はその場警戒だけを提示する

- Status: Accepted
- Date: 2026-08-09

## Context

警戒意図までは生成できるが、判断意図から実行前の行動候補へ接続する境界がなかった。
警戒意図から直接Entityやゲーム状態を変更すると、候補生成、選択、裁定、因果操作化の責務が混ざる。
経路探索、複数候補の比較、実際の停止や退避は現段階では過剰である。

## Decision

- 行動候補IDは呼び出し側が明示し、GUID、現在時刻、乱数から生成しない。
- 1件の警戒意図から `その場警戒` 候補を1件だけ生成する。
- 実行者ID、対象仮説、優先度は警戒意図の観測者ID、対象仮説、警戒度をそのまま使う。
- 由来警戒意図を説明可能性のため構造的に保持する。
- 警戒意図と行動候補に公開検証を設け、由来情報との不整合を拒否する。
- 候補生成と候補選択、実行、因果操作化を分離する。

## Consequences

- 判断意図から行動候補へ至る最小境界が成立する。
- 候補選択を独立した純粋処理として実装し、因果操作化をさらに後続へ分離できる。
- 行動候補はWorld Truth、行動結果、入力、因果操作ではない。
- 現時点では `その場警戒` 以外の候補を表現しない。

## Implementation Status

実装済み:

- 警戒意図と由来信念候補の整合性を確認する公開検証
- 行動候補ID、実行者ID、優先度、対象仮説、由来警戒意図を持つ契約型
- 1件の警戒意図から `その場警戒` 候補を作る純粋変換
- 地盤振動警戒経路から行動候補までの正式禊Test
- 正式な地盤振動発生因果操作から行動候補までの閉ループ統合
- 同一主体の候補一覧から最高優先度を入力順タイブレークで選ぶ独立した選択境界
- 選択済み候補を意味的な `エンティティ反応要求` へ変換する独立した下流境界

未実装:

- 複数の行動候補種別
- 候補評価、優先度再計算、ヒステリシス、cooldown
- 停止、移動、迂回、退避、攻撃、経路探索
- Entity・ゲーム状態更新、因果操作生成、Event発行、因果台帳追記
- 反応要求のEntity適格性検証と物理状態への写像
