# ADR-022: 選択済み行動候補は意味を保ったエンティティ反応要求へ変換する

- Status: Accepted
- Date: 2026-08-11

## Context

選択済み行動候補までは存在するが、実行や因果操作化の前段となる要求境界がなかった。
行動候補から直接ゲーム状態を変更すると、判断、要求、実行、因果操作化の責務が混ざる。
現行DomainにはNPC専用種別がなく、存在しないNPC契約を型名だけで装うべきではない。
また、`その場警戒` を即座に物理速度ゼロへ変換すると、意味層と物理層が癒着する。

## Decision

- 正式API名を `エンティティ反応要求` とする。
- 反応要求IDと発行Tickは呼び出し側が明示する。
- 選択候補の実行者ID、種別、優先度、対象仮説をそのまま保持する。
- 由来となる `選択済み行動候補` 全体を構造的に保存する。
- `その場警戒` は意味的な反応種別として保持し、具体的な速度、位置、巡路の変更へはまだ変換しない。
- 要求生成はゲーム状態、Entity一覧、Event、入力、因果操作、因果台帳を扱わない。
- private表現により、不整合な要求を外部から直接構築させない。
- 行動候補種別から反応種別への変換は明示的な判別共用体matchとする。

## Consequences

- 判断結果から実行要求へ至る説明可能な境界が成立する。
- 選択理由、選択位置、却下候補、同率最高候補、由来警戒意図を要求から辿れる。
- Entityの存在、種別、重複、現在状態は、後続の因果操作変換または実行器で検証する。
- 実際の停止、警戒姿勢、巡路保持をどの権威状態として表すかは後続設計となる。
- 反応要求はWorld Truth、行動結果、入力、Event、因果操作、因果台帳記録ではない。

## Implementation Status

実装済み:

- privateな `エンティティ反応要求`
- 明示的な要求IDと発行Tickの固定順検証
- `その場警戒` の意味を保つ明示的な種別変換
- 選択済み候補と全Provenanceを辿る公開アクセサ
- 因果認識経路と統合Replayからの接続検証

未実装:

- Entity適格性、存在、重複、終了状態の検証
- `その場警戒` の権威状態への写像
- 反応要求から因果操作への変換と実行
- Event発行、統合因果台帳追記、Replay
