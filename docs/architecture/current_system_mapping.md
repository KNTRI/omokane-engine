# 現行システム対応表

## 1. 目的

世界知能カーネルの新概念を、現在のv0.1コードと設計へ対応付ける。
`Existing`、`Partial`、`Missing`、`Deferred`、`Conflict` を使い、存在しない実装をあるものとして扱わない。

## 3. 現行直接更新の扱い

現在の `思兼神.更新する` は、入力一覧を現在状態へ直接適用し、プレイヤーのX座標とTickを更新している。
世界知能カーネルの最終経路とは異なるが、v0.1の通電確認として許容する。

今回リファクタリングせず、Movement Smokeも変更しない。
因果操作最小実行器はEntity位置変更だけを扱う並行経路として追加し、操作適用ではTickを進めない。
因果操作列の一括適用は、全件静的検証後に入力順で仮適用し、全件成功時だけEventと記録候補を公開する。
因果台帳の最小追記は、成功した記録候補だけを入力順で原子的に正式履歴へ変換し、失敗記録と因果操作ID重複を拒否する。
因果台帳の最小再生は、Tickと変更前位置を検証してEntity位置変更結果を入力順で再適用し、記録済みEventだけを再出力する。
地盤振動発生実行器は `因果操作種別.伝播信号生成` だけを受け入れ、ゲーム状態を変更せず、因果IDと実行者IDを由来として固定した権威伝播信号を生成する。
地盤振動発生記録は専用の成功結果であり、Entity位置変更専用の現行因果台帳へダミー位置を使って保存しない。
因果認識閉ループは、正式信号を既存の認識経路へ渡し、`その場警戒` 行動候補まで到達するが、候補選択や状態反映は行わない。
統合因果台帳は、Entity位置変更と地盤振動発生をダミー値なしで一つの因果順へ保存し、種別横断の因果操作ID一意性、Tick非減少、伝播信号ID一意性を保証する。
統合因果台帳再生は、位置変更を既存Replay helperで状態へ再適用し、地盤振動の記録済み信号と両種のEventを保存順で再出力する。失敗時は初期状態へ原子的に復帰する。
将来的には次へ移行する。

```text
入力意図
→ 因果操作
→ 天鳥船Motion
→ 世界状態反映
→ 言霊Event / 因果台帳
```

この差分は [ADR-003](../adr/ADR-003-causal-transaction.md) に記録する。

## 4. 権能Asset公開契約の扱い

現在の `権能Asset.発行Event一覧` はv0.1互換として維持し、今回変更しない。
将来的には次へ移行する。

```text
権能Asset
→ 神威Operation
→ 因果操作
→ Event / Trace / 因果台帳
```

移行時も既存Assetを黙って読み替えず、版管理または変換境界を設ける。

## 5. 今回の非目標

契約型、専用実行器、インメモリ台帳の追加は、実行基盤の完成を意味しない。
汎用異種因果操作、位置変更・地盤振動以外の因果結果、候補選択と行動実行、統合因果台帳の永続化と完全再シミュレーション、Snapshot、伝播計算、地表記憶、身体システム、LOD、常駐制御は今後の独立作業とする。
